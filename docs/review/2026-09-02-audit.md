## P0 — a real defect, measured

### 1. Rare coins and glide coins are placed 192 px too high

`rare_coin_spawner.gd:183`, `glide_coin_spawner.gd:186` and `:230`.

`get_terrain_height()` is **`ground_y`-relative**, not TerrainGenerator-local.
`coin_spawner.gd:29` states this correctly — *"in the same local-y units build_chunk_surface
uses (get_terrain_height() is already ground_y-relative)"* — and every other placement in the
project honours it:

| Spawner | How it lands in world space | Correct? |
|---|---|---|
| `CoinSpawner` | group node at `position.y = ground_y`, coin local to it | ✅ |
| `GroundTreeSpawner` | group node at `position.y = ground_y` | ✅ |
| `ObstacleSpawner` | `ground_y + get_terrain_height(x) - half_height` | ✅ |
| `PowerupSpawner` | `ground_y + get_terrain_height(x) - clearance` | ✅ |
| **`RareCoinSpawner`** | `get_terrain_height(x) - clearance` — **no `ground_y`** | ❌ |
| **`GlideCoinSpawner`** | `get_terrain_height(x) - clearance` — **no `ground_y`** | ❌ |

Both offending files carry a header comment asserting the opposite:

> *"this node sits directly under TerrainGenerator with no offset of its own, so a coin's local
> position IS already in the same space `get_terrain_height()` returns."*

The first half is true and the conclusion does not follow. `CoinSpawner` and
`GroundTreeSpawner` sit directly under TerrainGenerator too — they get it right by putting the
**group node** at `y = ground_y`, which these two files have no equivalent of.

**Measured**, with a throwaway probe that instantiated `main.tscn`, called each spawner's own
placement function and compared `get_surface_world_y(x)` against the node's real
`global_position.y` (probe deleted afterwards; tree verified clean):

```
TG.global_position.y = 0.00  ground_y = 192.00  surface_world_y = 309.62
RARE  x=7000  clearance above surface = 366.00   (expected 174.0)
GLIDE         clearance above surface = 392.00   (expected 200.0)
OBST          centre above surface    =  16.00   (expected half-height)  ← control, correct
```

`366 = 174 + 192`. `392 = 200 + 192`. The obstacle control is exact.

**What it costs.**

- **The rare coin's entire premise is void.** `RARE_COIN_CLEARANCE = 174` is derived, not
  tasted (`rare_coin_spawner.gd:37-58`): grab ceiling is `58 + 128·m²`, so **186 px at max
  upgrade** and **314 px holding the ×√2 powerup**. At an actual 366 px the diamond is
  **unreachable at every jump level, with or without the powerup**. The one object in the game
  whose position is a statement about the upgrade tree has never made that statement. It is
  presumably only ever collected by accident, from inside a glide.
- **The glide coin field is 192 px off the ground it is anchored to.** The whole point of
  `TRAIL_CLEARANCE_MIN = 60` is coins that skim the surface at the bottom of the spread; they
  are at 252. The end-of-glide bonus diamond at `BONUS_SURFACE_CLEARANCE = 130` lands at 322 —
  also above the 314 px powerup ceiling.

**The fix is one term in three lines** (`terrain_generator.ground_y +`), matching what
`ObstacleSpawner`/`PowerupSpawner` already do, plus a correction to both file headers.

**NOT APPLIED, deliberately, and the two halves are not equally safe:**

- The **rare coin** half is unambiguous — it restores a derived, documented, gate-asserted
  number that the placement currently contradicts. Low risk.
- The **glide field** half moves all 30 coins down 192 px. That spread was tuned by eye
  (*"the full field's vertical spread lands in the thousand-plus-px range"*,
  `glide_coin_spawner.gd:20-28`) — at the wrong offset, so the tuning needs a second look
  in play, not just a corrected constant. `HANDOFF.md` also says playtest findings outrank
  other work and not to tune by eye. **Owner's call.**

## P1 — why no gate caught it, and what would

### 2. Every item-height gate is constant-only. None measures a placed node.

`terrain_invariant_check.gd`'s `check_rare_coin_height()` (:717), `check_coin_line_height()`
(:769), `check_upgrade_curve()` (:897) and `check_obstacle_clearance()` (:950) all assert
**derivations between constants** — that 174 sits in the gap between jump levels, that the
curve ends at 1.0, and so on. Not one of them instantiates a spawner or looks at where an
object actually ends up. So finding #1 is invisible to the gate whose stated job is exactly
that number, and would stay invisible to any future frame-of-reference slip.

This is the gap worth closing, and it is small:

```
check_spawn_placement()   # ~40 lines, joins terrain_invariant_check's scene-needing block
  for each of the six spawners:
      call its own placement function at a known x
      assert  get_surface_world_y(x) - item.global_position.y  ==  its declared clearance
```

It is the only gate shape that can catch a parent-frame mistake, and it generalises: any new
spawner is one row. Cheap, and it turns a class of silent bug into a build failure.

### 3. `shipping_values_check` misses two knobs it is meant to cover

The gate exists because every debug knob here is a plain `var` invisible to every other gate.
Two plain vars are not in it:

- **`RareCoinSpawner.debug_spawning_disabled`** (`rare_coin_spawner.gd:34`). Same class as
  `ObstacleSpawner`'s and `PowerupSpawner`'s, both of which **are** checked. No gate sets it
  and no gate checks it, so left `true` and committed it silently deletes the 25-value pickup
  from the shipped game.
- **`PowerupSpawner.debug_first_powerup_effect_override`** (`powerup_spawner.gd:52`).
  `shipping_values_check.gd:270-274` prints it under *"editor-only (is_debug_build, not
  checked)"* and the comment there says *"both derive from `OS.is_debug_build()`"* — **that is
  true of the time override on line 47 and false of this one**, which is a plain `&""`. Left
  set, it pins the first powerup of every run in a release build.

Both are one `expect_*` line each.

### 4. Five of the six terrain weight knobs are unchecked

`debug_weight_flat / small_hill / medium_hill_valley_mix / big_downhill / gentle_uphill`
(`terrain_generator.gd:22-26`) — only `debug_weight_mega_drop` is asserted. They are `@export`s,
so a *scene* override is caught by the text scan, but an edited source default is not. Five
more `expect_int` lines against the `DEFAULT_WEIGHT_*` constants.

## Organization

Both of these are real but neither is urgent, and both are the kind of change that can
introduce bugs — flagging rather than doing.

### 13. `terrain_generator.gd` is 2188 lines carrying five separable jobs

Chunk lifecycle (598–700), surface/fill geometry (703–835, 1089–1200), **ice painting and the
shader interface** (836–1088, 2070–2188), the height field and segment cache (1204–1760), and
chasm + lake scheduling (1377–1550).

The ice-painting block is the clean seam: ~470 lines that take points and colours and never
touch the height field, segment cache, chasms or the lake. Extracting it as a
`TerrainIcePainter` the generator owns would take the file to ~1700 and give the ice work its
own file to match `shaders/ice.gdshader`. **The risk is what makes it a flag, not a task:**
`repaint_chunk` walks node names, `refresh_ice_appearance` is the one place the biome and the
lake blend fold together, and both are exercised only by the three windowed visual gates —
which cannot run headless. It needs the visual tier plus an owner look, not a quiet refactor.

### 14. `scripts/systems/` is 26 files across six unrelated concerns

Spawners (6), background and sky (7), the frozen lake (3), persistence and progression (3),
biome (2), audio/input/misc (5). Subfolders would make the directory answer "what kind of
thing is this?" the way `scripts/debug/` vs `scripts/debug/archive/` already does. Cost: every
move rewrites a `.uid`, an `ExtResource` path in `main.tscn`, and `preload()` strings — with
`main.tscn` in the blast radius, which is the file the project already warns about most.
Worth doing only bundled with something else that already touches the scene.

## Confirmed healthy — checked, no action

- **Every `res://` reference in the project resolves.** No orphaned `.uid`, no orphaned
  `.import` (the two `art_source/*.import` leftovers from the last review are gone).
- **Dead code is near zero.** Three uncalled public functions in the shipping tree
  (`AchievementManager.is_unlocked`, `PowerupManager.is_effect_active`,
  `UpgradeStore.is_maxed`) — all legitimate API surface — and one unused constant (#10).
- **All six spawners defer seed-derived init to the first `_physics_process`.** The documented
  `_ready()` ordering trap is not present anywhere.
- **World rebasing is handled everywhere it must be.** `SkateTrack` and `SkateSpray` track
  `total_world_rebase_shift` explicitly; `LakeReflection` follows the camera; `SnowDrift`,
  `SkyBackdrop`, `BirdFlock` and the parallax layers are screen-space; everything under
  `TerrainGenerator` inherits the shift.
- **No palette aliasing.** `BiomeDirector.blended` is one reused scratch Resource, and all
  eight consumers copy values out rather than holding the reference.
- **The shield bookkeeping between `Player` and `PowerupManager` is sound** in both orderings
  (glide-shield-then-powerup and powerup-then-glide-shield), including
  `end_effect(EFFECT_SHIELD)` firing for a shield the manager never granted.
- **Playtime double-counting (2026-08-24 review P0 #1) is genuinely fixed** —
  `GameManager.get_unbanked_seconds()` exists and `FrozenLakeDirector` uses it. Every path out
  of PLAYING banks, and the two restart paths are only reachable from PAUSED/DEAD, where
  banking already happened.
- **`check.sh` is honest.** Mutation-tested claims in it still hold; the export-content check
  really does fail on a forbidden path.
